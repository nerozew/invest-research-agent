# 工程开发规则

- 除非用户明确改变范围，否则每一轮只能执行 `docs/05-DEVELOPMENT-ROADMAP.md` 中的一个任务 ID。
- 修改文件前，必须检查当前文件和 `git diff`，保留用户已有的修改以及与当前任务无关的工作。
- 如果一个任务超过路线规定的小任务学习粒度，应先停止并提出拆分方案，不能直接开始实现。
- 必须保持依赖方向：`adapters/API/infrastructure -> application -> domain`。`domain` 不得导入 CrewAI、FastAPI、SQLAlchemy、Redis 或任何云厂商 SDK。
- 模块边界必须使用有类型的 Pydantic 模型。已经定义 schema 时，不得使用原始 `dict` 在模块之间传递数据。
- 所有网络 I/O 都必须显式设置连接超时和读取超时，并对错误进行分类。重试次数必须有上限，而且只能重试可恢复错误。
- 不得随意使用范围过大的 `except Exception`。只有在应用边界中记录错误、转换错误类型并重新抛出时才允许使用，绝不能用它隐藏失败。
- 数据库 schema 的变化必须提供可回滚的 Alembic migration，并测试 `upgrade` 和 `downgrade`。
- 实现功能时必须新增或更新相应测试。不得为了让任务通过而删除测试、跳过测试、降低断言强度或改写测试目的。
- 除非当前任务明确要求测试真实服务，否则外部服务必须使用 mock 或 fixture。
- 不得添加真实的 API key、token、Cookie、登录凭据或个人联系方式。`.env.example` 只能包含占位符。
- 必须运行与当前任务直接相关的最小测试，以及必要的 lint 和类型检查；只能汇报真正执行过的命令和真实结果。
- 只有全部验收条件真正通过后，才能给路线中当前任务 ID 添加 `✅`；没有 `✅` 的任务仍然视为未完成。
- 不得实现下一个任务，不得顺便重构无关代码，也不得在没有批准 ADR 的情况下替换已经确定的技术方案。
