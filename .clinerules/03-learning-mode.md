# 学习模式

- 修改文件前，必须先使用通俗中文说明实施计划，计划最多包含六个可以实际执行的步骤。
- 优先选择能够独立测试的最小纵向切片或最小单元修改。
- 引入某个库的新功能时，必须指出它在代码中的具体使用位置，并解释为什么需要这个功能。
- 实现完成后必须停止，并汇报：任务目标、修改文件、关键决策、实际验证结果、三个学习知识点、一个暂时不提供答案的检查问题、已知限制以及下一任务建议。
- 在用户尝试回答检查问题之前，不得直接给出答案。
- 如果不确定官方 API 或当前版本库的行为，必须查阅最新的官方一手文档，不得凭记忆猜测。
- 如果测试没有运行或没有通过，任务仍然属于未完成状态，必须直接说明真实情况。
